# PC 投屏助手（电脑 → 电视机顶盒）

把电脑的**全屏画面**、**某个程序窗口**、**本地媒体文件**或**任意网络链接**投屏到电视机顶盒/电视上。
本程序面向您的机顶盒（192.168.5.6，魔百和 B863AV3.1-M2）开发，**优先使用机顶盒自带的 DLNA 能力，无需安装任何 APK**；仅在 DLNA 实时推流不稳定时，可用「仅URL」模式配合机顶盒上的 VLC 作为兜底。

## 原理

```
┌────────── 电脑 (192.168.5.222) ──────────┐        ┌────── 机顶盒 192.168.5.6 ──────┐
│  ffmpeg 采集(全屏/窗口) → H.264 编码      │  HTTP  │  内置 DLNA 渲染器              │
│  ↓ 本地 HTTP 服务 (端口 8090)            │───────▶│  (当贝投屏G1 / 多屏互动L2 /     │
│  媒体文件直接通过 HTTP 提供              │  UPnP  │   MiPT / 我的小电视)            │
│  UPnP 推送 SetAVTransportURI + Play ─────│───────▶│  收到地址后自行拉流并播放       │
└──────────────────────────────────────────┘        └────────────────────────────────┘
```

- **媒体文件投屏**：PC 起一个 HTTP 服务提供文件，然后用 UPnP 告诉机顶盒去播放（和手机 App 投屏完全一样的机制）。
- **网络链接投屏**：把 http(s) 视频/直播流/m3u8 链接直接推给机顶盒，由机顶盒自行拉取播放。
- **全屏/窗口实时投屏**：ffmpeg 用 `gdigrab` 采集屏幕（全屏或指定窗口）→ H.264 编码（默认软编 libx264，可启用硬件加速 h264_mf）→ 实时 MPEG-TS 流（或 HLS 分片流）→ 同样通过 UPnP 推给机顶盒播放。

## 环境要求

- **Python 3.8+**（本机已有 3.12.3），仅用标准库，无需 pip 安装任何包。
- **ffmpeg**：仅「屏幕/窗口投屏」需要（本机已检测到 `C:\ffmpeg-standalone\bin\ffmpeg.exe`）。
- 电脑与机顶盒在同一局域网（本机检测为 192.168.5.222）。

## 快速开始

### 图形界面（推荐）

双击 **`启动投屏助手.bat`**（或 `py run_gui.py`），窗口启动后会自动最大化，或运行：

```
py run_gui.py
```

1. 机顶盒 IP 默认 `192.168.5.6`，点 **发现设备**；
2. 在设备下拉框选目标（默认已选最佳设备）；
3. 点 **投屏全屏** / **投屏窗口**（先点「刷新窗口」在下拉框选窗口）/ **投媒体文件**；
4. **投网络链接**：在「网络链接」输入框粘贴 http(s) 地址 → 点「投网络链接」（机顶盒需能访问该地址）；
5. 参数（默认已偏流畅）：帧率 12、码率 2M、分辨率「原始」、策略「自动」、硬件加速默认不勾（软编兼容性最好）；
   还卡就降低 帧率(10或8) / 分辨率(540 或 360) —— 比调码率更有效；
6. **声音**：默认勾选「同步声音到电视」（屏幕/窗口投屏时把电脑系统声音一起投到电视）；
   媒体文件/网络链接投屏时，文件自带的音轨也会正常在电视上播放。
7. 停止：点 **停止投屏** 或关窗口。

### 命令行

```
py run_cli.py discover                        # 发现设备
py run_cli.py windows                         # 列出可投屏的窗口
py run_cli.py media --file "D:\视频\电影.mp4"  # 投屏媒体文件
py run_cli.py url --url "https://example.com/video.mp4"   # 投屏网络链接
py run_cli.py url --url "https://.../live.m3u8"           # 投屏 m3u8 直播流
py run_cli.py screen --mode full              # 投屏全屏（默认带声音）
py run_cli.py screen --mode window --title "Chrome"   # 投屏某个窗口（带声音）
py run_cli.py screen --mode full --audio off         # 只投画面不带声音
py run_cli.py screen --mode full --encoder libx264      # 强制软编；auto=硬件加速(h264_mf优先)
py run_cli.py screen --mode full --resolution 540 --fps 10 --bitrate 2M   # 降分辨率+帧率更流畅
py run_cli.py screen --mode full --strategy hls       # 改用 HLS 策略
py run_cli.py screen --mode full --strategy url       # 只启动流，在机顶盒 VLC 手动打开
py run_cli.py stop                             # 停止
py run_cli.py volume                           # 查看/设置渲染器音量
```

### 防火墙（重要）

机顶盒要访问电脑上的 8090 端口拉流。第一次运行时如果 Windows 弹出防火墙提示，请选 **"允许访问"**；
也可以右键以管理员身份运行 `tools\open_firewall.ps1` 提前放行 8090~8099 端口。

## 声音同步到电视

- **媒体文件投屏**：文件自带的音轨会随视频一起在机顶盒上播放，无需额外设置。
- **屏幕/窗口实时投屏**：默认同时采集电脑系统声音并同步到电视。原理：
  系统声音 →（默认播放设备临时切到 `CABLE Input`）→ VB-CABLE 虚拟声卡 →
  `CABLE Output` 被 ffmpeg 采集 → 与画面一起编码进流 → 机顶盒播放。
- 声音采集设备自动检测顺序：`CABLE Output`（VB-CABLE）→ 立体声混音/Stereo Mix → 其他。
- 投屏期间电脑自带喇叭会静音（声音转到电视），**停止投屏后自动恢复原默认播放设备**。
- GUI 勾选框「同步声音到电视」可随时关闭；命令行用 `--audio off` 关闭，`--audio auto` 自动检测，
  也可以直接给设备名（如 `--audio "CABLE Output (VB-Audio Virtual Cable)"`）。
- **电脑没有 VB-CABLE 时的方案**：
  1. 优先启用声卡自带的「立体声混音」：声音设置 → 录制 → 右键空白处勾选"显示禁用的设备" →
     如果列表里有「立体声混音」就启用它，程序会自动检测到；
  2. **如果列表里根本没有"立体声混音"选项**（很多笔记本/新声卡没有），那就必须安装虚拟声卡：
     管理员运行 `tools\install_vb_cable.ps1`（自动下载安装 VB-CABLE，免费），重启后程序自动检测到
     `CABLE Output`；也可以用其他虚拟声卡/调音台（如 Voicemeeter）。

## 投屏策略说明

| 策略 | 延迟 | 流畅度 | 说明 |
|---|---|---|---|
| MPEG-TS（默认策略「自动」通常走此） | 较低（约2~5秒） | 取决于渲染器实时流处理能力 | 单条连续流，实时性好；若盒子处理弱会掉帧发卡 |
| HLS | 较高（约4~8秒） | 通常更稳 | 切成 1 秒小分片文件让盒子下载，乐播类盒子兼容好；卡顿时值得一试 |
| 仅URL(VLC) | 较高 | **最流畅** | 程序只把流发到电脑上，你在盒子 VLC 里手动打开地址，由 VLC 自行缓冲，一般最不卡 |

**建议**：先试「自动」（MPEG-TS）；仍卡 → 换「HLS」；还卡 → 用「仅URL(VLC)」在盒子 VLC 里打开（最保底最流畅）。

**编码自动回退**：默认使用软件编码（x264，兼容性最好，实测多屏互动L2 稳定）。勾选"硬件加速编码"后，
如果电视上没能真正开始播放（程序会检查渲染器是否真的拉取到了流数据），会自动改用软件编码重试一次，
再不行会自动改试 HLS——不会一直卡死；代价是启动时可能多等几秒。

**画面卡顿怎么调（按有效程度排序）**：
1. **降分辨率**（最有效）：GUI「分辨率」选 540 或 360（或 CLI `--resolution 540`）。编码负载主要看
   分辨率×帧率，码率影响很小——**接受模糊的话，把分辨率降下来画面会立刻顺很多**；
2. **降帧率**：帧率从 15 降到 10 甚至 8（CLI `--fps 10`）；
3. **硬件加速编码**：默认**不勾选**（软编 libx264，兼容性最好）；勾选后可大幅降低 CPU 负担；
4. **换策略**：HLS 或 仅URL(VLC)；
5. 码率（`--bitrate 2M`）对"卡"帮助不大，主要影响清晰度，模糊一点无所谓的话不用刻意调低。

## 可选：机顶盒安装 APK 作为兜底（一般不需要）

如果 DLNA 实时推流在您的盒子上不稳定，可安装 **VLC for Android**：

1. 机顶盒打开"开发者选项 → USB 调试 / ADB 调试"（魔百和一般在 设置→通用→关于本机 连续点击版本号）；
2. 下载 VLC APK（arm64，https://get.videolan.org/vlc-android/）；
3. 电脑上运行：`powershell -ExecutionPolicy Bypass -File tools\install_vlc_apk.ps1 -BoxIp 192.168.5.6 -ApkPath C:\path\to\vlc.apk`；
4. 之后用「仅URL(VLC)」策略，在机顶盒 VLC 的"网络串流"里粘贴程序显示的地址即可。

> 说明：您的盒子已自带 乐播(多屏互动L2)/当贝投屏G1/MiPT 等多个 DLNA 渲染器，本程序的媒体投屏和实时投屏实测都不需要额外安装 APK。

## 常见问题

- **窗口列表是空的**：点「刷新窗口」即可（旧版存在该 bug，已修复）；目标窗口需要可见、未被最小化。
- **投屏窗口时切到别的窗口，电视画面定格/没了（声音还有）**：这是 Windows 屏幕采集(gdigrab)的固有行为——
  被采集的窗口被遮挡或最小化后就不再产生新画面。请保持被投窗口可见（可以点一下让它回到前台），不要最小化/关闭它；
  或者改用「投屏全屏」。
- **投网络链接没画面**：确认该链接在电脑浏览器里能打开、且机顶盒能访问（公网链接需盒子能上网；
  内网链接需盒子和目标在同一网络）。
- **画面卡顿**：默认使用软件编码（libx264，兼容性最好）；若 CPU 占用高但仍卡，可勾选 GUI 的“硬件加速编码”，或降低帧率(10)/分辨率(540)；网络建议用 5G 频段。
- **电视没声音**：确认 GUI「同步声音到电视」已勾选（或 CLI 未加 `--audio off`）；确认安装了 VB-CABLE
  或在声卡里启用了立体声混音；看日志里是否出现"声音采集: ..."；停止后默认播放设备会自动恢复。
- **电视黑屏 / 渲染器一直 STOPPED**：换策略（自动→MPEG-TS→HLS→仅URL），或调低码率（2M）帧率（10）；个别盒子对实时流缓冲较慢，等 10~20 秒再看。
- **画面卡顿**：降低帧率（10）和码率（2M~4M）；无线网络建议用 5G 频段。
- **延迟大**：实时流一般有 2~8 秒延迟（取决于机顶盒缓冲），属正常现象。
- **发现不到设备**：确认机顶盒与电脑同一网段；盒子上投屏应用是否在前台；多点几次「发现设备」。
- **窗口投屏显示黑屏/找不到窗口**：目标窗口需要可见且未被最小化；窗口标题要和 `run_cli.py windows` 列出的一致。
- **机顶盒拉不到流**：检查 Windows 防火墙是否放行 8090 端口（见上）。
